|Term|Definition|
|---|---|
| **Client** | A human operator who interacts with the *Ermes Infrastructure* to execute *Functions*. |
| **Developer** | A human operator responsible for writing and deploying *Functions* on the *Ermes Infrastructure*. |
| **Network Provider** | A human operator responsible for defining and deploying the *Ermes Infrastructure*. |
| **Function** (?) | A self-contained piece of software that takes an input and produces an output. |
| **Stateful Function** | A *Function* designed to access and utilize data stored in persistent memory through a database. |
| **Infrastructure** (?) | The underlying components and services that support the operation of a system, such as computational units, storage, and networking. |
| **Ermes Node** (?) | A software component that represents the basic operating unit within the *Ermes Infrastructure*. |
| **(Physical) Node** | A physical computational unit, such as a server or a computer, within a distributed *Infrastructure*. |
| **(Logical) Node** | An instance of an *Ermes Node* deployed on a *(Physical) Node*. |
| **Group Token Provider** (?) | A software component that manages and provides authentication tokens to *Clients*, enabling them to access functionalities within the *Ermes* platform. |
| **Function Registry** | A software component responsible for storing and enabling the retrieval of *Functions* created by *Developers*. |
| **Ermes Infrastructure** | The interconnected system of *Ermes Nodes*, *Group Token Provider*, and *Function Registry*, organized to mirror the physical topology of the underlying network. |
